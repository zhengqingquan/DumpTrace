# DumpTrace 能力规划

> 目标：在现有「异常画像 → 符号 → 规则 → 内存使用 → 时间线/栈 → 导出现场」之上，把死机包（`.ass` / logel / `.mem` / 旁路文件）里**尚未系统解析**、但对定位有价值的信息逐步吃透。  
> 规划能力面向展锐/UIS 类 Logel `*_armlog` **通用反查**，不绑定某一产品或业务线；下文举例仅为说明场景类型。  
> 本文是规划，不代表已实现；已落地能力见 [功能清单](功能清单.md)、技术路径见 [反查技术路径](反查技术路径.md)。

---

## 1. 现状摘要（已具备）

| 类别 | 能力 |
|------|------|
| 接入 | `*_armlog` / dump 布局、`.axf`/`.map` 配对、符号分项匹配 |
| ASS | Assert / Fault / 线程 / 寄存器 / 版本 / 编译时间 |
| 符号 | PC/LR/Exception → addr2line |
| 规则 | 空指针、Abort、线程提示、OOM、内存/队列/栈压力、锁等待、回调重叠、时间线故事线、泄漏嫌疑 |
| 内存 | System/Static 池、段 ALLOC/FREE、Allocated Top、专用池、`leak_suspects` / `fragmentation` |
| Logel | 死机前关键字时间线 + 模块聚类/主故事线（复用 logel2txt） |
| RTOS/P1/P2 | 任务/定时器/队列、同步原语、MMI、回调列表、PS（可 skip） |
| MEM | 出事线程栈切片 + 候选调用栈 |
| 工程化 | 现场导出、批量、diff、配置、打包 |

| 优先级 | 主题 | 主数据源 | 一句话价值 | 状态 |
|--------|------|----------|------------|------|

| P0 | 定时器列表 | `.ass` timer list | 周期回调由谁驱动 | 已落地 → `timers.txt` |
| P0 | 队列水位 | ASS 各线程 Queue_* | 消息是否堆积 | 已落地（并入 tasks / 规则） |
| P1 | 锁 / 信号量 / Event | ASS Mutex/Sem/Event | 死锁与长时间占用 | 已落地 `sync_objects.*` |
| P1 | 专用内存池 | 专用 Space / cache 池头 | 主池之外的分区缺口 | 已落地（扩展 `mem_usage`） |
| P1 | MMI / UI 状态 | ASS MMI info | 当前窗体、控件、焦点 | 已落地 `mmi_state` |
| P2 | 时间线模块聚类 | logel / traceview | 按可配置模块聚合死机前行为 | 已落地（`timeline` + `[timeline_modules]`） |

建议落地顺序：**P0 → P1 → P2 → P3**；若只先做一项，优先 **全任务表 + 定时器列表**。

## 3. P0：任务 / 定时器 / 队列

### 3.1 全任务表

- **来源**：ASS「Print tasks info」或等价任务列表块。
- **拟抽取**：线程名、ID、状态、优先级、栈起止/高水位、入口或关联队列名。
- **产出建议**：`tasks.txt` / `tasks.json`；`scene.md` 摘要「可疑线程」（非 Ready 久、栈占用高、与 Assert 线程相关）。
- **规则候选**：`stack_near_overflow`、`task_blocked`、`assert_thread_not_running`。

### 3.2 定时器列表

- **来源**：ASS「Print timer list information」。
- **拟抽取**：timer id、周期/剩余、回调地址（再符号反查）、所属模块线索。
- **产出建议**：`timers.txt`；Top 高频回调及其符号（显示 / 多媒体 / 网络等按符号名归类，词典可配置）。
- **规则候选**：`periodic_timer_active`（与 OOM、显示刷新等路径叠加时提高置信度）。

### 3.3 队列水位

- **来源**：当前线程及任务表中的 `Queue_Total` / `Queue_Used` / `Queue_Available`。
- **拟抽取**：各队列使用率；Used 接近 Total 的队列列表。
- **产出建议**：并入 `tasks` 或独立 `queues` 摘要。
- **规则候选**：`queue_pressure`（使用率 ≥ 阈值）。

## 4. P1：同步原语 / 专用池 / MMI

### 4.1 Mutex / Semaphore / Event

- **来源**：ASS Mutex / Semaphore / Event list。
- **拟抽取**：名称、持有者、等待者、计数。
- **价值**：死锁、优先级倒置、关中断过久的旁证。
- **规则候选**：`lock_held_by_X`、`waiters_gt_0`。

### 4.2 专用内存池

- **来源**：ASS 中非 System/Static 的池/Space 头（如电话本池、字库 cache 等，以实包字段名为准）。
- **拟抽取**：与主池相同的 Total/Avail/Used 或块统计；无对应段则跳过。
- **价值**：主池接近耗尽时，专用分区可能另有耗尽或泄漏。
- **产出建议**：扩展 `mem_usage`（`pools[]` 增加专用池），不必新文件格式。

### 4.3 MMI / UI 状态

- **来源**：ASS「Print MMI info」。
- **拟抽取**：当前窗体/控件、动画相关句柄、焦点。
- **价值**：与显示刷新、动画定时器等路径交叉验证（不绑定具体业务符号名）。
- **产出建议**：`mmi_state` 小节写入 `scene.md`。

---

## 5. P2：时间线加深 / 回调 / PS / 堆分析（已落地）

### 5.1 时间线模块聚类

- **来源**：现有 timeline（logel2txt Trace）+ **可配置**模块词典（`[timeline_modules]`）。
- **抽取**：按 `display` / `audio` / `camera` / `usb` / `network` 等分桶计数；死机前 N 秒「主故事线」一句话。
- **产出**：`timeline_by_module.json`；`scene.md` 故事线摘要；规则 `timeline_storyline`。

### 5.2 回调函数列表

- **来源**：ASS `Callback Function List`（各任务栈 `Entry at [addr]`，非独立 timeout 回调表）。
- **抽取**：回调地址 → 符号；标记与 Assert/Exception 重叠项。
- **产出**：`callbacks.txt` / `callbacks.json`；规则 `callback_list_present` / `callback_assert_overlap`。

### 5.3 PS 任务队列 / 调用栈

- **来源**：ASS「PS tasks queue」「PS function call stack」。
- **抽取**：协议栈任务队列水位与栈帧；**仅有菜单无表体时 `skipped`**，不中止分析。
- **产出**：`ps_info.txt`；规则 `ps_queue_pressure`。

### 5.4 堆占用加深（基于已有 mem_usage）

- **来源**：`Allocated memory info` + 段内 ALLOC 表 + Assert 文案中的申请 size。
- **增强**：按文件聚合泄漏嫌疑分；申请 size vs 最大空闲（碎片 vs 真 OOM）。
- **产出**：`mem_usage` 的 `leak_suspects[]`、`fragmentation`；规则 `leak_suspect` / `heap_fragmentation`。

---

## 6. P3：旁路文件与深挖

### 6.1 `.lst` / LogSave 元数据

- **来源**：`*_armlog` 下 `.lst`，ASS 中 `Dump LogSave ArmLog/DspLog/IQ Memory` 等说明。
- **拟抽取**：抓取通道、起止、是否空文件；报告「现场完整性」。

### 6.2 `.mem` 对象窗口

- **来源**：`*_1.mem` + Fault/指针地址 + axf。
- **拟抽取**：指定地址前后十六进制窗口；可选按类型启发式（需符号/结构知识，分阶段）。
- **说明**：不做完整堆遍历 GUI；先窗口 + 标注。

### 6.3 Fat / NV / iram

- **来源**：ASS 对应 Print/Dump 段。
- **价值**：存储损坏、NV、紧耦合 RAM 等偶发问题；默认降优先级，按需开启。

---

## 7. 规则与导出约定（规划统一）

新增解析模块时尽量遵守：

1. **解析与展示分离**：`parse_*` → 结构体 / dict；`render_*_txt`；`scene.md` 只放摘要。  
2. **缺段可降级**：无对应 ASS 段 → `skip` + 警告，不中止分析。  
3. **规则可插拔**：新证据通过 `apply_rules(..., xxx=)` 或统一 `EvidenceBundle` 传入。  
4. **脱敏**：报告、文档与测试夹具不用真实姓名/客户名、本机绝对路径、密钥、未公开工程标识；示例用 `DEMO_*` / `<REPO_ROOT>` / `EX1234` 等占位。  
5. **产物命名**：`tasks.*` / `timers.*` / `sync_objects.*` 等与现有 `mem_usage.*` 并列；大文件仍仅 `--full` 拷贝。  
6. **通用优先**：默认词典与规则不写入特定客户/业务品牌名；项目差异通过配置扩展。

## 8. 明确仍不做（保持边界）

与 [功能清单](功能清单.md)「明确不做」一致，规划阶段也不纳入：

- 自动生成修复补丁 / 保证唯一根因  
- 替代 Logel 完整协议解码 UI  
- 通用 IDE/GUI 产品化

## 9. 验收建议（按主题）

| 主题 | 最小验收 |
|------|----------|
| 任务表 | 金样本或脱敏样本包能列出 ≥1 张任务表，Assert 线程可对齐 |
| 定时器 | 能列出条目；有 axf 时回调可符号化为非空 |
| 队列 | 能计算使用率并在压力高时告警 |
| 锁/信号量 | 能解析持有者/等待者字段（格式以样本包为准） |
| 专用池 | 至少识别一种非 System/Static 池并计入摘要（有则测、无则 skip） |
| 时间线聚类 | 死机前窗口输出分模块计数 + 一句摘要 |
| 堆加深 | Top 模块与「申请失败 size vs 最大空闲」对比出现在报告中 |

具体字段正则以样本 ASS 为准，实现前对 1～2 个典型死机包做格式锚定（与现有 mem_usage 方式相同）；入库材料须先脱敏。
