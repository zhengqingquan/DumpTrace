# DumpTrace 功能清单

从展锐 `*_armlog` 死机包：接入 → 解析 ASS → 符号 / 规则 →（可选）时间线与 MEM → 导出现场 / 批量 / 对比。

---

## 一、能力总览

| 能力 | 说明 |
|------|------|
| 死机包接入与校验 | 识别 `*_armlog` 布局，配对 `.axf`，版本一致性检查 |
| ASS 异常画像 | 抽出 Assert / Fault / 线程 / 寄存器 / 版本 |
| 地址符号反查 | PC / LR / Exception → 函数 / 文件 / 行（addr2line 等） |
| 规则判读 | 空指针+偏移、Abort 类型、线程名启发式、OOM、内存/队列/栈压力、周期定时器 |
| Log 丢包可信度 | 读 `*_log_stat.txt`，报告中标注 |
| 任务 / 定时器 / 队列 | 全任务表、栈水位、定时器模块归类、队列使用率 |
| 同步原语 / MMI | Mutex/Sem/Event 持有与等待；MMI 窗体/控件/动画句柄 |
| 回调 / PS | Callback Function List（Entry→符号）；PS 队列/栈（有则解析，无则 skip） |
| Logel 时间线 | 死机前 N 秒关键字事件 + 模块聚类/主故事线（复用 [logel2txt](https://github.com/zhengqingquan/logel2txt)） |
| MEM 栈 / 候选调用栈 | 按 Stack 区切片，启发式抽返回地址再反查 |
| 导出死机现场 | 可转发的摘要 + 证据；Markdown / JSON |
| 批量分析 | 目录下多个 dump，汇总表 |
| 现场对比 | 两次 dump 差异（线程、Fault、符号等） |
| 配置文件 | `dumptrace.toml` |

---

## 二、能力明细

### 1. 包接入 `ingest`

- [x] 输入：`armlog` 目录，或上层 `dump_*`（自动找 armlog + axf）
- [x] 识别主包 vs `_pb`（默认主包）
- [x] 枚举：`.ass` / `.logel` / `*_1.mem` / `*_log_stat.txt` / `.lst` / `.axf` / `.map`
- [x] 输出清单：路径、大小、是否可用
- [x] 缺 ASS 中止；缺 AXF 降级
- [x] 符号匹配分项：文件名片段 / 编译时间 / Build ID / map 入口与摘要指纹

### 2. ASS 解析 `ass_parser`

- [x] Assert 文案、Exception 地址、DFSR / Fault、Fault address
- [x] 线程名 / ID、队列、栈起止、TCB
- [x] PC / LR / R0–R12 / CPSR 及各模式 R13 / R14
- [x] Project / Platform / HW Version、编译时间
- [x] 内存相关线索（如 `rvosmem.c(line)`）
- [x] ASS 内重复 assert 块去重

### 3. 符号反查 `symbolizer`

- [x] `DUMPTRACE_ADDR2LINE` / `--addr2line`
- [x] 批量反查：PC、Exception、SVC LR 等
- [x] Thumb 地址 LSB 处理
- [x] 输出：`addr → func / file:line`
- [x] 无工具时警告，仍导出「仅寄存器」现场

### 4. 规则与可信度 `rules` / `credibility`

- [x] `fault_addr` 小偏移 → `null_deref`
- [x] Abort / Permission / Translation → `data_abort`
- [x] 线程名启发式 → `thread_hint`
- [x] No memory / unable to allocate → `oom_assert`
- [x] 池使用率 ≥85%/95% → `mem_pressure`
- [x] `log_stat` → 抓 log 可信度
- [x] 队列使用率 ≥ 阈值 → `queue_pressure`
- [x] 栈高水位 ≥ 阈值 → `stack_near_overflow`
- [x] Assert 线程与任务表对齐 / 等待态 → `assert_thread_not_running` / `task_blocked`
- [x] 周期定时器（re_init>0）→ `periodic_timer_active`
- [x] Mutex 持有 → `lock_held_by_X`；等待者>0 → `waiters_gt_0`
- [x] 专用池使用率 ≥85% → `dedicated_pool_pressure`
- [x] 回调列表存在 / 与 Assert 地址重叠 → `callback_list_present` / `callback_assert_overlap`
- [x] PS 队列压力 → `ps_queue_pressure`（无 PS 段则 skip）
- [x] 时间线主故事线 → `timeline_storyline`
- [x] 堆碎片 / 泄漏嫌疑 → `heap_fragmentation` / `leak_suspect`

### 4.1 内存使用 `mem_usage`

- [x] System / Static Space：`Total_Num` / `Avail_Num` / `Max_Used` / `Threshold`
- [x] Base / App / ISR 等段：ALLOC/FREE 字节与块数、最大空闲、按文件 Top
- [x] `Allocated memory info` 汇总与 Top 占用
- [x] 专用池（如 font cache / `*_POOL`）：并入 `pools[]`（`kind=dedicated`）
- [x] 泄漏嫌疑 `leak_suspects[]`（按文件聚合占比/块数）；`fragmentation`（申请 size vs 最大空闲）
- [x] 导出 `mem_usage.txt` / `mem_usage.json`，摘要写入 `scene.md`

### 4.2 任务 / 定时器 / 队列 `rtos_info`

- [x] `Tasks info`：线程名 / ID / 状态 / 优先级 / PC / 队列 All·Avail
- [x] `Stack info`：TotalSize / Max_Used / Available，合并进任务表
- [x] 当前线程与任务表 `Queue_*` 使用率；压力队列列表
- [x] `timer infomation`（含拼写变体）+ Active Threads 定时器：名 / rem / re_init / 链表指针
- [x] 定时器按可配置模块词典归类；导出 `tasks.txt` / `tasks.json` / `timers.txt`
- [x] `scene.md` 摘要可疑线程与定时器模块分布

### 4.3 同步原语 `sync_objects`

- [x] Mutex：Name / Owner / TotalSuspended / OwnershipCount
- [x] Semaphore：Name / Counter / Suspend Task_Name
- [x] Event：Name / CurrentFlag / TotalSuspended / SuspendList
- [x] 导出 `sync_objects.txt` / `sync_objects.json`；持有锁与等待者摘要进 `scene.md`

### 4.4 MMI / UI `mmi_state`

- [x] `s_handle_list`：APPLET / WINDOW / CTRL 节点（handle / id / name / parent）
- [x] `s_zorder_system` 焦点窗体；动画类控件；`s_layer_arr` 图层
- [x] 导出 `mmi_state.txt`，摘要写入 `scene.md`

### 4.5 回调列表 `callbacks`

- [x] `Callback Function List`：Current / Task N 的 `Entry at [addr]`
- [x] Entry 地址进符号反查；与 Assert/Exception 地址重叠标记
- [x] 导出 `callbacks.txt` / `callbacks.json`，摘要写入 `scene.md`

### 4.6 PS 信息 `ps_info`

- [x] `PS tasks queue` / `PS function call stack`（有表体则解析；仅菜单则 `skipped`）
- [x] 导出 `ps_info.txt`；队列压力进规则

### 5. 时间线 `timeline`

- [x] 死机前 3s / 10s / 60s 关键字窗口 → `timeline.txt`
- [x] 可配置模块词典聚类 + 主故事线一句话；可选 `timeline_by_module.json`
- [x] 复用 [logel2txt](https://github.com/zhengqingquan/logel2txt)（同级 / `PYTHONPATH` / `DUMPTRACE_LOGEL2TXT`）
- [x] DumpTrace **不**实现 Export Trace 解码本身
- [x] `--skip-timeline` 可跳过

### 6. MEM 与候选调用栈 `mem_stack` / `callstack`

- [x] 基址映射（默认 / ASS 的 `0x80000000`）
- [x] 栈区 → `stack.bin` / `stack.hex`
- [x] 栈上疑似 LR → 符号 → `callstack_candidates.txt`
- [x] `--skip-mem` 可跳过

### 7. 导出死机现场 `export_scene`

目录：`out/<dump_id>_scene/`

| 产物 | 内容 |
|------|------|
| `scene.json` | 结构化现场（画像 + 符号 + 规则 + 内存使用 + 索引） |
| `scene.md` | 一页纸报告 |
| `assert_excerpt.txt` | ASS 关键段摘录 |
| `symbols.txt` | 地址反查表 |
| `mem_usage.txt` / `mem_usage.json` | 内存池/段/分配表摘要 |
| `tasks.txt` / `tasks.json` | 全任务表、栈水位、队列与可疑线程 |
| `timers.txt` | 定时器列表与模块归类 |
| `sync_objects.txt` / `sync_objects.json` | Mutex / Sem / Event 与持有/等待摘要 |
| `mmi_state.txt` | MMI 窗体/控件/图层状态 |
| `callbacks.txt` / `callbacks.json` | Callback Function List（Entry→符号） |
| `ps_info.txt` | PS 队列 / 调用栈（有则写出） |
| `timeline_by_module.json` | 时间线模块聚类计数与主故事线 |
| `manifest.json` | 源文件哈希 / 路径 / 工具版本 |
| `evidence/` | 可选拷贝 |

模式：

- [x] 默认：摘要 + 引用
- [x] `--copy-ass`：附带 ASS
- [x] `--bundle`：`*_scene.zip`
- [x] `--full`：再拷贝 mem / logel（体积大）

现场至少包含：版本与时间、线程与 Abort/Assert、Fault 与寄存器、PC/LR 符号（若有 axf）、源路径与工具版本。

### 8. 批量与对比 `batch` / `diff`

- [x] `dumptrace batch <父目录>` → `summary.csv`
- [x] `dumptrace diff A B` → `diff.json` / `diff.md`

### 9. CLI 与配置

```text
dumptrace analyze <dump_or_armlog> [--axf PATH] [--out DIR] [--bundle] ...
dumptrace batch <父目录> [--out DIR]
dumptrace diff <A> <B> [--out PATH]
dumptrace version
```

- [x] 退出码：0 成功 / 1 包无效 / 2 符号失败（`--strict-symbols`）
- [x] `dumptrace.toml` / `dumptrace.example.toml`
- [x] 金样本字段回归（`tests/`）

## 三、明确不做

- 自动生成修复补丁
- 替代 Logel 完整协议解码 UI
- 保证「根因唯一正确」（只给证据链 + 假设）
- GUI / IDE 插件

---

## 四、技术选型

- 语言：Python ≥ 3.8（见 `pyproject.toml`）
- 入口：`dumptrace` / `dumptrace.py`
- 测试：`python -m unittest discover -s tests -v`（不强制入库巨型 `.mem`）
- 打包：`requirements.txt` + `dumptrace.spec` → `dist/dumptrace.exe`
- 外部：可选 addr2line；时间线依赖 logel2txt
